# 字体选择与渲染

## 当前字体

通用简中文本采用 **Noto Sans CJK SC SemiBold（字重 600，版本 2.004）**，从官方可变字体生成静态 600 字重，保留完整字符覆盖。字体来源与构建方法见[构建与部署](build.md)。生成的字体 bundle、原版游戏资源及本机截图不随仓库提交。

若恋对白、姓名及原 `FOT-UDMarugo_SmallPr6-B` 控件采用 **Resource Han Rounded SC Bold（字重 700，版本 1.910）**，使用独立字体包与原控件的纵向度量。若恋按钮图片也使用同一份 Bold 字体；来源由 `config/love-font-source.json` 和 `config/ui-label-images.json` 的 SHA-256 固定。

Resource Han Rounded 的静态字库以 gzip 保存在 `font-sources/`，沿用 SIL Open Font License，许可证随模块提供。该静态版本从官方 1.910 可变字体固定 `wght=700`、`ROND=100`，移除不兼容的 GPOS 表，再转换为 CFF1；字符映射与字形轮廓保持一致。

默认模式为 `replace-ui`，字体由模块 AssetBundle 提供；兼容保留原字体资源的旧 `add-font` 游戏载荷：

- 普通界面文字默认整段使用 Noto Sans CJK SC SemiBold，包括纯英文、标点、展示柜 TAG、公告 PR 和各类固定标签。新增控件无需逐项加入替换白名单。
- 纯数字及常见符号组合（例如 `1,000`、`＋1655`、`10%`、`08:00:00`、`1/10`）保留原字体；含文字或富文本标签时按控件规则处理。
- 商店与兑换所已确认的售价控件整组保留原字体，币种符号、逗号与单位一起保留；独立的“免费”中文标签仍用替换字体。
- 好友列表中的昵称、`Lv` 和等级数字整行统一使用替换字体，纯数字昵称也遵循这条规则。
- `GOODS / GOODS CASE`、`STORY`、`LIVE` 大型装饰标题，以及首页、LIVE 页紧凑等级徽章保留原字体与原材质。`VENUS RANK`、事务所 `RANK` 上方标题照常替换，下方等级保留原字体。
- 例外集中在 `app/src/main/cpp/ui_font_policy.h`，按确认过的控件路径或数值格式判断，不按任意英文名称触发。
- 剧情字幕、人名、HomeTalk 和竖屏活动继续使用各自的字号、描边与度量配置；完整独立简中字库不会按缺字逐个混合原字体。

普通剧情、HomeTalk 与若恋对白可分别启用“标点使用原版字体”。该选项只让指定标点从原字体取字形，仍由 TMP 处理材质；正文、人名和原始文本内容不变。

原生钩子在字形查找前使用最终字符缓冲决定字体，并同步材质和图集。绘制前复核静态标签与预制件字体重设，保留已建立的受限空间度量；不会用滞后的文本 getter 把数值控件恢复原字体。更换字体路由模式需要对应 APK 和重启，不能仅依靠词典热更新。

当前独立字体模式只从插件字体包加载替换字体。暂时加载失败会重试，不再扫描并缓存旧修补 APK 中同名的 RHR 字体。通用字体对象名为 `Localify-DefaultCJK`，圆体为 `Localify-LoveRoundedSC`，均不带字重名称。部署检查分别读取两份字体配置的 family、字重与哈希。图片中的文字按 `config/ui-label-images.json` 生成，不参与运行时字体选择。

插件的长期字体缓存同时保留托管引用和 Unity 原生资源，防止切换场景后旧引用仍在、字体材质与图集已被回收。普通剧情的样式模板和独立描边材质也保持原生资源有效；读取缓存时检查原生对象，失效后从保存的样式重新绑定图集。按控件生成的临时字体副本清除继承的保活标志，继续随控件释放。更改此逻辑后应重复进出使用不同原字体的页面，不能只检查重启后的首次显示。

## 场景差异

剧情字幕、人名、HomeTalk、竖屏活动及受限尺寸的界面控件各自维护参数。调整依据是 Unity 控件尺寸、字体度量及材质，不能只按模拟器截图像素设置全局偏移。参数与预览方式见[字体配置](font-profiles.md)。

展示柜底部的 ID 搜索按钮跟随好友搜索、标签搜索的共同纵向位置，修正原预制件中的额外偏移。按钮继续由原 FitToChild 组件计算宽度；不把父宽度反向赋给文字，避免父子尺寸互相依赖。

TMP 描边会同时影响字面与外缘，应配合字面膨胀参数调整，避免吞掉笔画。需要修改材质的控件使用独立材质，防止影响其他文字；首次显示、后续赋值和控件复用都需核对。

### 普通剧情的原版描边

游戏 6.0.2 的普通剧情预制体中，字幕与姓名均引用 `Solis-MK5 SDF`。其材质基线为：

| 对象 | 原字号 | 描边宽度 W | 字面扩张 D | 描边颜色 |
| --- | --- | --- | --- | --- |
| `Message Label` | 54 | 0.35 | 0.35 | 黑色 |
| `Name Label` | 32 | 0.50 | 0.50 | 白色 |

原版字幕的字间距为 16。这里的字号和间距是 TMP 控件参数，实际屏幕尺寸还取决于画布缩放；它们与生成字体图集时的采样字号不是同一个参数。

当前默认沿用字幕字号 54、字间距 16，人名保持原字号 32；字幕与人名的 W/D 分别为 0.35/0.35 和 0.5/0.5。过场正文的颜色与透明度继续由游戏控制，包括灰色文字与淡入淡出；只有人名的黑字白边使用独立颜色配置。

两种材质的描边柔化均为 0。原版采用 `D = W`，使向外扩张抵消描边向内侵占字面的部分。忽略柔化、额外字重与抗锯齿时，字面边界的相对变化取决于 `D − W`；最终距离还取决于字体图集和材质比例，参数本身不是屏幕像素。

原版图集采样字号为 34，`GradientScale = 8`。普通剧情使用单独的动态字体缓存，采样字号 90，按原字体 `(GradientScale − 1) × FaceInfo.scale / pointSize` 换算 padding，并限制为最多 16，使描边比原版归一化范围略窄；游戏 6.0.2 对应 padding 16、`GradientScale = 17`。其他界面继续使用默认 padding 9。只有剧情的完整父路径、原字号和原描边同时匹配时才选用此缓存，避免扩大其他 UI 的描边。

padding 通过 `CreateFontAsset` 的完整参数在字形生成前设置；只增大材质的 `GradientScale` 不会生成缺少的距离数据。材质绑定及参数预览后调用控件自身的 `UpdateMeshPadding`，同步描边留白及比例。TMP 仍会根据字面扩张、描边和软化自动计算 `ScaleRatioA`，所以 W 不是像素，也不与可见宽度线性对应。细标点和相邻字形仍需在实际画面检查。

消息选择等高度受限控件使用共享替换字体图集的独立字体副本，按原字体比例保留纵向度量。原生渲染逻辑保留针对首次赋值、字形预生成与材质提交的处理，避免首句或滚动复用时出现差异。

## 构建与验证

字体构建检查完整原文和译文的可见字符覆盖、原资源保留情况、字体模式与载荷配对，以及最终 APK 的嵌入和签名。通过检查只说明文件与字形条件满足，不等于所有画面排版均正确。

改变字体或 TMP 钩子后，在独立设备核对普通剧情字幕与人名、HomeTalk 首句和后续对白、竖屏活动、列表滚动返回，以及纯英文数字标签。游戏版本或控件路径变化时重新验证对应规则。

`preserve-non-cjk` 保留旧的含汉字／假名才整段替换规则，也使用 `add-font`。`replace-all`、`replace-translated` 等更早模式使用 `replace-fot`；切换前必须核对配套字体载荷。

BGM 曲名范围保存在生成文件 `app/src/main/cpp/showcase_bgm_titles.h`。更新本地 MasterDB 后运行 `python3 tools/build_showcase_bgm_titles.py`，从本地完整 `ShowcaseMusic.json` 关联 `Music.json` 生成；也可用 `--showcase`、`--music` 指定输入。缺失或无效输入会终止生成并保留现有文件，未知新增曲名继续遵循默认字体规则。该范围仅供旧 `preserve-non-cjk` 策略使用；当前 `replace-ui` 无需按曲名添加字体规则。该生成文件变更需要重新构建插件。
