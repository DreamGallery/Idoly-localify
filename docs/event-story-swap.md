# 活动剧情替换

详细设置的「剧情播放」中并列提供卡片剧情替换、普通活动剧情替换、「实验性 · 特殊活动剧情替换」。每类先选实际播放剧情，再选已开放的同类入口；每类独立保存，并提供一键恢复。设置只影响下次进入，不能解锁入口或下载缺少的模型、配音等资源。

普通活动采用 MasterDB `EventStory -> Story.advAssetIds` 关系。特殊活动指若恋，采用 `LoveStoryEpisode -> Story.advAssetIds`；`LoveStoryEpisode.assetId` 有些是 `love-story-*` 展示资源，不能当作 TXT 名。目录只接受单一 ADV 资产且 `advPlayTypes == [1]` 的记录。普通活动中包含额外 Live/多段资产的剧情暂不提供，否则替换一段后仍会接上原入口的后续演出。

`tools/story_event_catalog.py` 生成 `event-stories.json`、`love-stories.json`，并已接入 `pipeline.py build/verify`。若恋部分第7/8话失败结局共用脚本，选择页合并并标明共用，不虚构不同资源；结局、角色分支分别标注。运行时只列本机已安装且通过格式检查的资源，数量可能较少。若恋译文保留原脚本的 branch/branchgroup 行。

## 格式与边界

两类均以 `[timeline]` 结束并通过 Octo TXT 资源提供。若恋额外包含 `choicegroup`、`branchgroup`、`branch`、`bgmplay`、`bgmstop`，因此三类不能混用；完整读取源脚本，不拆分或重写选择分支。选择项及分支以顺序和 `groupLength` 编码，已检查的这些标签中未见服务端分支 ID。

特殊活动保留 `Choice` 和 `Condition` 分支，直接替换完整 TXT。`Love.Start` / `Love.Restart` 返回的 `advBranchInfos` 以 `groupIndex`、`index` 提供条件分支选择；插件不改写这个响应。选择页显示选项组数和每组选项数，只提供两者一致的入口；保存时再次检查，原生读取也会对不匹配的组合回退到原入口，避免初始化选项时越界。条件分支不因此保证一致，能加载脚本并不代表能还原源活动路线。

若恋没有独立回顾入口，只能使用活动期间已开放的剧情入口。选项提交、完播和活动进度仍归原入口；恢复替换只能恢复本地资源映射，不能撤回已推进的服务端进度。

播放页顶部和开场话数/标题使用已审定目录元数据，在已知 `StoryPlayerScreen` 路径下且原文字匹配时临时替换。普通和特殊活动常为无参数 `[title]`，不能套用卡片的角色标题解析器。角色名和入口介绍没有足够的活动专用证据，维持原入口；不改 MasterDB。卡片的角色/标题切换保持原有逻辑。

状态分别位于 `story-swap.json`、`story-swap-event.json`、`story-swap-love.json`，沿用有界、原子写入格式。每个状态只认自己的资源前缀；缺失/损坏源、截断脚本、不兼容入口退回原入口。只有卡片支持 `_short` 别名，活动不推测短版。删除对应状态即可恢复，不触碰译文文件。

## 设备验证

1. 普通活动优先使用已读入口，检查内容与标题，再恢复并确认入口原剧情。
2. 特殊活动在明确允许推进测试活动进度后，检查加载、选项及条件分支；按实际脚本记录结果，不把一种脚本的成功推广到全部活动。
3. 一键恢复后确认对应映射已清除，其他两类设置保留。
4. 缺少资源或分支上下文不匹配时记录现象与日志，避免将仅加载成功描述成完整播放验证。
