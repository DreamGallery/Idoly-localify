# 高级画质、账号备份与服务器连接

在悬浮窗打开「详细设置」：高级画质和自定义服务器位于「额外功能」，账号备份与导入位于「账号与数据」。这些功能不依赖翻译开关。

## 高级画质

可设置目标帧率、3D 渲染倍率，以及 FXAA 或 SMAA 抗锯齿。「跟随游戏」保留原设置，「恢复游戏默认」取消全部覆盖。

设置在游戏运行时应用，保存后下次启动继续使用。实际帧率受屏幕刷新率、设备性能和温度限制，选择 120 FPS 不代表一定能达到 120 FPS。

渲染倍率保持画面比例，最长边限制为 4096 像素，总像素不超过 8,388,608。指定倍率时关闭游戏的自动降分辨率；正式拍照的指定输出尺寸保持不变。FXAA / SMAA 会开启所需的后处理。

## 账号备份与导入

先进入游戏，使账号数据完成同步，再打开「账号备份与导入」。设置至少 8 位密码，可选择包含自己拍摄的照片原图，然后导出。

默认位置为 `Download/Idoly-localify/accounts/`；Android 9 会要求自行选择保存位置。`.idolyaccount` 文件包含登录凭据和账号数据，使用密码加密。请同时保管文件与密码，不要上传到公开仓库或 Issue。

导入时选择文件、输入密码并核对账号 ID，随后选择：

- **恢复官方账号登录**：重启游戏后切换账号，进度从官方服务器读取。标题页可能暂时显示旧 ID，进入游戏后刷新。登录凭据失效或官方认证服务停止后，这种方式不能保证继续登录。
- **导入完整快照到本机**：保存客户端已同步的数据和所含照片，不覆盖官方服务器进度。
- **导出服务器数据包**：生成未加密 ZIP，供兼容服务器导入。包含进度与所选照片，不包含官方登录凭据；仅交给自己信任的服务端。

快照包含客户端当前掌握的卡牌、服装、道具、剧情等账号数据，不包含服务器内部记录、排行榜等未同步内容。停服后恢复仍需要兼容的本地或自建服务器；插件本身不是离线服务器。下载目录中的备份由用户自行保管，不随普通缓存清理删除。

## 自定义服务器

填写服务器地址和该服务器的独立登录凭据，保存后重启。凭据由兼容服务器提供；也可由服务端登记页面中的随机生成值。不要填写官方 Firebase 令牌或账号引继密码。

默认要求 HTTPS。使用私有 CA 时填写 PEM 证书；留空使用网络库默认信任的证书。HTTP 仅允许本机回环地址，例如 `http://127.0.0.1:50051`。

此功能只接管游戏 gRPC。资源下载、网页、Firebase 存储等仍访问原服务，不能仅靠修改地址就让所有功能离线运行。服务端必须实现当前客户端的协议和业务逻辑。

自定义模式下使用独立身份，官方账号引继接口被阻止。连接失败不会自动切回官方服务器；要恢复时点击「恢复官方连接」并重启。官方账号的导入和导出需先恢复官方连接。

## 兼容服务器的数据约定

服务器数据包采用以下结构：

| 文件 | 内容 |
| --- | --- |
| `metadata.json` | 格式版本、游戏版本、账号标识和采集时间 |
| `snapshot.json` | 当前 `UserGetResponse` 的 JSON 数据及字段覆盖信息 |
| `snapshot.pb` | 同一份 `UserGetResponse` 的 protobuf 二进制数据 |
| `photos/index.json` | 照片 ID、原文件名、数据包内路径及 SHA-256；导出照片时提供 |
| `photos/*` | 所选照片原图，以内容哈希命名 |

服务端应根据游戏版本选择匹配的 protobuf 定义，自行导入账号进度、建立照片存储映射；插件不会自动上传数据包。

客户端保留游戏原有 gRPC 编码方式。`System.Check` 和 `Auth.Login` 的 `FirebaseIDToken` 字段在自定义连接中承载独立登录凭据；服务端通过 `AuthLoginResponse.GameAuthToken` 返回自己的会话令牌，后续以 `x-auth-token` 发送。服务端不应要求用户提供官方 Firebase 凭据。
